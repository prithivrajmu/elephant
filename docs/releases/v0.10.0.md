# Elephant 0.10.0

Stops reworded lessons from being saved as new memories. Before, only a
byte-identical lesson was caught.

## Near-duplicate lessons

- Before a lesson is saved, Elephant compares it with every lesson the author can
  recall in the same place: project lessons for this project, personal lessons and
  this conversation's lessons. Team drafts are not compared.
- A similar lesson under the same conditions makes the save fail. The error lists
  up to three similar lessons with their IDs and scopes.
- The agent then does one of these:
  - If its lesson adds nothing, it saves nothing.
  - If its lesson corrects or extends a listed lesson, it resends with `supersedes`
    set to those IDs. They are retired, not deleted, in the same save, and the new
    lesson keeps the IDs.
  - If its lesson is different, it resends with `distinct_from` set to the listed
    IDs.
- `record_memory` accepts `supersedes` and `distinct_from`. `distinct_from` is not
  stored.

## How it was chosen

Similarity is TF-IDF cosine over stemmed words and whole code identifiers such as
`QUERY_CACHE_DISABLED`, with threshold 0.22. The design follows agent memory
systems such as Mem0 and Zep: a cheap similarity search finds candidates, and the
agent decides.

In a labelled replay of 159 real saves, 20% repeated or updated an earlier lesson.
The check caught 72% of those pairs. 9% of saves were refused with no duplicate
listed, mostly for related lessons. Word overlap, BM25, character n-grams and
sentence-level matching did no better. The threshold was tuned on the first half
of the saves and checked on the second half.

The comparison is lexical. A paraphrase that shares few words is still saved.

## Changed behaviour

- The same lesson with only a new `source` is now refused. Before, it was saved
  as a separate memory.
- A personal lesson that copies one saved from another project is refused, because
  personal lessons are recalled in every project.
- The hosted Cloudflare backend is unchanged and still catches only identical
  lessons.

## Security

Release builds use Go 1.27.3. It fixes GO-2026-6809 in `crypto/x509`, which
`govulncheck` reports against Go 1.27.2 through the dashboard's HTTP code.

## Upgrade

```sh
npx --yes elephant-memory@0.10.0
elephant version
```

No store migration is required. Restart running agents and Memory Palace after
installation. Packages remain unsigned, and Windows uses MCP without automatic
hooks.
