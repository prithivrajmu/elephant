# Elephant 0.13.0

Elephant adds dreaming: a review of stored lessons between tasks. Your coding
agent checks the original evidence, corrects outdated advice, or consolidates
compatible lessons. Elephant saves each replacement with source-check provenance
and retires its exact inputs in the same transaction. Scope and applicability
stay intact. Original evidence remains in the journal.

You can request one review through your connected agent, or opt in to automatic
reviews after foreground work stops. No change is a valid result.

## Run one review

Ask your connected agent to run the `memory_dream` MCP prompt, or say:

> Run one Elephant dreaming pass. Check the original sources before saving any
> correction or consolidation. Report what changed and what remains uncertain.

The workflow uses `dream_memory` to prepare a bounded batch and `commit_dream`
to save a checked replacement. The CLI exposes the same steps:

```sh
elephant dream --root /path/to/project --budget 16000 --limit 10
elephant dream-commit --root /path/to/project --file checked-replacement.json
```

`dream` prepares work; your agent must review the sources and create the checked
replacement file before `dream-commit`. Use the same identity and project
configuration for both commands. See the [dreaming guide](https://github.com/prithivrajmu/elephant/blob/main/docs/dreaming.md) for the
JSON format, pagination and source checks.

## Enable automatic idle reviews

Install or refresh normal project hooks, then approve them through your agent's
normal flow. With an installed, logged-in Codex CLI available, run:

```sh
elephant init --root /path/to/project
elephant dream-schedule --root /path/to/project --enabled=true
elephant dream-schedule --root /path/to/project
```

Complete a foreground task to arm the first pass. By default, a review waits
10 minutes after all tracked sessions stop. Attempts have a 6-hour cooldown,
a limit of 4 per UTC day per project/identity context, and a 2-minute timeout.
Each pass prepares at most 10 memories within 16000 bytes and permits up to
3 replacements. Successful passes process one page, then wait for new work.

The Codex reviewer runs in a fresh read-only session with inherited MCP servers
and hooks disabled. Elephant alone validates and saves proposals. Resumed
foreground activity cancels the reviewer; each save also rechecks activity and
input revisions. A persisted watcher lease prevents overlapping runs.

Inspect `ready`, `wait_reason` and the optional `next_eligible_at` to see why a
review is waiting. Status also reports saved IDs and oversized inputs. Pause
and cancel idle reviews with:

```sh
elephant dream-schedule --root /path/to/project --enabled=false
```

The [guide](https://github.com/prithivrajmu/elephant/blob/main/docs/dreaming.md#automatic-idle-scheduling) covers custom limits,
trusted command adapters, abandoned sessions and watcher recovery.

## Reliability fixes

- Oversized memories appear in a bounded skip list without blocking later
  memories. A page containing only skipped inputs advances without a model call.
- Elephant validates the full proposal set before saving, including disjoint
  inputs, scope, source checks, sensitive content and writing policy.
- Reviewer JSON must match the output contract exactly. Duplicate keys,
  case-mismatched fields, nulls and malformed results produce `invalid_output`.
- Command reviewer output now obeys the 256 KiB limit during subprocess copying.
  Excess output is rejected without retaining raw runner diagnostics.

## Limits

Automatic reviews are opt-in and use the reviewer's existing login and provider
allowance. The limits above do not impose an exact token or currency cap.
Elephant does not add transcript collection or independently verify the agent's
source-check assertions. Tests cover lifecycle and validation; live reviewer
quality, downstream accuracy and cost improvements remain unbenchmarked.

Dreaming supports owned private memories in the local backend. The Cloudflare
backend does not implement it. Cloud sync refuses scopes containing derived
memories because sync v1 cannot preserve their lineage; use local backup for
those scopes. Each replacement is atomic, but a later commit rejection can
leave earlier valid saves in place. Check saved IDs before retrying.

## Upgrade

```sh
npx --yes elephant-memory@0.13.0
elephant version
```

Restart running agents and Memory Palace after upgrading. Run `elephant init`
in each project to refresh hooks and guidance. Existing idle scheduler settings
are preserved; upgrading does not opt you in.
